# Gourmand

Online ordering for Gourmand, Пловдив: the public site (Bulgarian at `/`,
English at `/en`), checkout with delivery by district or pickup, Stripe card
payments with manual capture, and a Bulgarian owner admin at `/admin`.

Stack: Next.js 16 (App Router) · React 19 · Tailwind CSS 4 · Supabase
(Postgres, Auth, Storage) · Stripe Checkout · Resend · Vitest · Playwright.

Scope and business rules: [docs/backend-scope.md](docs/backend-scope.md).
Status and what's still open: [docs/backend-report.md](docs/backend-report.md).

## Local development

Needs Docker (for local Supabase) and Node 22+.

```bash
npm install
npm run db:start        # local Supabase on ports 553xx, writes .env.development.local, creates the local owner
npm run db:fixture      # TEST DATA: confirms hours, publishes this week with 20 portions per dish
npm run dev             # http://localhost:3000, admin at /admin
```

The local owner's sign-in is in `.env.development.local` (`DEV_OWNER_EMAIL`,
`DEV_OWNER_PASSWORD`). Password-reset emails land in Mailpit at
http://127.0.0.1:55324.

Your own keys go in `.env.local` (names in [.env.example](.env.example)), never
in chat or commits:

- `STRIPE_SECRET_KEY` — test mode (`rk_test_…` preferred). Then
  `stripe login` once and `npm run stripe:listen`; copy the printed
  `whsec_…` into `STRIPE_WEBHOOK_SECRET` and restart `npm run dev`.
- `RESEND_API_KEY`, `EMAIL_FROM` — without them emails stay in the outbox
  as "failed" and can be retried from Админ → Имейли.

Background jobs: `npm run cron` calls `/api/cron` every minute (owner
reminders, email retries, expired holds). In production Vercel Cron does this
(`vercel.json`); pg_cron also expires holds and anonymises old orders.

## Database

- Migrations: `supabase/migrations/`. Seed: `supabase/seed.sql`, generated by
  `npm run seed:build` from `src/data/menu/*.json`, `supabase/seed-data/` and
  the photos in `public/images/menu/` (uploaded to the `dish-photos` bucket).
  Import notes for the owner: [docs/menu-import-report.md](docs/menu-import-report.md).
- `npm run db:reset` rebuilds the seed, resets the local database and
  recreates the local owner. `npm run db:types` regenerates
  `src/lib/database.types.ts`.
- Nothing is exposed through the Supabase Data API: RLS is on for every table
  with no policies for `anon`/`authenticated`, and only the server's secret key
  has grants. Atomic work (portion reservation, status changes, refunds) runs
  in Postgres functions.

## Tests

```bash
npm test            # unit tests (pricing, hours, validation, statuses, emails, links)
npm run test:db     # integration tests against local Supabase (stock, payments, webhooks, RLS)
npm run test:e2e    # Playwright, desktop + phone, against the dev server
```

E2E tests pin the clock to Tuesday 20 Oct 2026, 12:00 Sofia (a cookie for the
server, `page.clock` for the browser; the cookie is ignored in production) and
load their own local test data in `tests/e2e/global-setup.ts`.

## Not done here on purpose

No deployment, no live Stripe, no changes to gourmand.bg or its Cloudflare
DNS. Each needs separate approval.
